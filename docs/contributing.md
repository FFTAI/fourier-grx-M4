# 贡献指南

欢迎通过 [Issue](https://github.com/FFTAI/fourier-grx-M4/issues) 或 Pull Request 改进文档与示例。无论是修正错别字、澄清操作步骤，还是补充接口说明，都请尽量提供可核对的信息。

## 反馈问题

提交 Issue 时，建议包含：

- 相关文档页面的 URL 或仓库文件路径。
- 当前内容存在的问题，以及期望的修正或补充。
- 涉及机器人行为或接口时，注明机器人型号、`fourier-grx` 版本和运行模式。
- 涉及示例代码时，注明运行目录、执行的命令、完整错误信息和开发环境；请勿提交密码、令牌等敏感信息。

## 提交修改

1. 将修改控制在清晰、集中的主题内，避免同时夹杂无关的全文格式化。
2. 修改中文页面时，同步更新 `docs/en/` 下的英文对应页面；修改示例时，同时检查相关示例文档是否仍然准确。
3. 对照实际命令、配置和代码路径核对技术内容，不要将未经验证的推断写成确定事实。
4. 在 Pull Request 中概述修改内容、涉及页面和已完成的检查；涉及行为变更时，请附核对依据。

## 文档约定

- 页面通常需要 `layout: default`、`title` 和 `nav_order`；子页面还需要正确的 `parent`，父页面按现有导航结构配置 `has_children: true`。
- front matter 的键顺序统一为 `layout`、`title`、`parent`、`nav_order`、`has_children`、`has_toc`、`nav_exclude`。
- `has_toc` 只控制父页面的自动子页列表，不是正文目录；正文目录使用 `* TOC` 加 `{:toc}`。不要使用不存在的 `toc_min_header` / `toc_max_header`，也不要把 `{:toc}` 单独放在正文中。
- 任务页按类别编号并保持与 `docs/tasks.md` 的任务索引一致：基础控制 4.01–4.05、零点与校准 4.06–4.09、被动运动 4.10–4.14、助力运动 4.15–4.22、膝受限 4.23–4.30、腿长调节 4.31–4.32、规划器 4.33、急停保护 4.34、算法专题 4.35。编号统一使用两位小数（如 `4.10` 而非 `4.1`），避免与 `4.1x` 在数值排序时合并。新增任务应插入对应类别并在必要时重排后续编号。
- 文档页中的站内链接和资源路径通常以 `/fourier-grx-M4/` 开头；根目录 README 使用仓库相对路径。
- 新增任务页面时，同步维护中英文任务总表、任务索引及相关接口映射，不要只增加孤立页面。
- 命令、文件名、接口字段和版本号使用行内代码格式，并保持中英文页面的技术内容一致。
- 固件发布页里被 `<!-- BEGIN GENERATED version-table -->` 标记包围的版本表由 `tools/gen_release_table.py` 从发布索引与正式版本台账生成，不要手工增删行或改「发布性质 / 支持状态」两列；每个版本的「更新内容」小节仍是人工撰写。
- 标记与表格、与相邻正文之间必须各留一个空行。kramdown 把 HTML 注释当作块级原始 HTML，会吞到下一个空行为止——紧贴正文或表格会让整张表失去 Markdown 解析，页面上显示成裸管道文本。移动标记位置时一并保留这些空行。

## 提交前检查

本仓库没有已检入的统一构建、测试或 lint 工具链。提交文档修改前，请至少检查：

- 新增或修改的站内链接、图片和其他资源路径是否有效。
- 页面 front matter 是否符合所在章节的导航结构。
- `docs/` 与 `docs/en/` 的对应页面是否同步。
- 示例命令、运行目录、依赖和安全前提是否清楚且与当前代码一致。
- 版本表与发布索引/台账是否一致：`python3 tools/gen_release_table.py --check`（有漂移时用 `--write` 重新生成，`--manifest <文件>` 可离线校验）。

感谢所有帮助改进 Fourier-GRX-M4 SDK 文档与示例的贡献者。
