# 高抬腿 DSP 前向行走

## 任务信息

| 任务 | 任务值 (TID) | 控制方式 |
|---|---|---|
| 高抬腿 DSP 前向行走 | **4134** | PD |
| 高抬腿 DSP 前向行走 + 速度前馈 | **4135** | PD + 速度前馈 |

适用机型：M4L（P1 / T1 / T2）。

任务描述：

- 在普通 DSP 前向行走的基础上增加摆动脚抬升补偿：先计算原 DSP 轨迹的实际足端位置，再在摆动区间按目标离地高度重解髋 / 膝角，最后进行零相位平滑。
- 目标是补偿髋角缩放与平滑造成的实际抬脚损失，不改变支撑腿轨迹，也不承诺基座前进量。
- 4135 复用 4134 的轨迹与面板参数，仅增加速度前馈。T2 的 FSA v3 协议会直接下发速度前馈；P1/T1 的 FSA v2 fast 帧没有速度字段，相关参考轨迹补偿只影响可视化，不修改实际关节目标。
- 启动、停止、暂停、过力矩保护及 Dynalink 上报均沿用[被动前向行走](/fourier-grx-M4/docs/tasks/forward_walk_passive)。

## 任务参数

| 面板参数 | 含义 | 默认值 | 说明 |
|---|---|---|---|
| `param_1` | 步长 | 0.5 m | 与普通前向行走一致 |
| `param_2` | 步行速度 | 0.5 m/s | 与普通前向行走一致 |
| `param_3` | 补偿后的目标抬脚峰值 | 10 cm | 单位 cm，允许范围 5～25 cm；≤0 或未发送时沿用当前值 |
| `param_6` | 基座高度 | 自动 | 与普通前向行走一致 |
| `param_7` | DSP 原始足端抬升高度 | 0.10 m | 作用于补偿前的 DSP 轨迹，与 `param_3` 的最终离地目标不同 |
| `param_8` | 双支撑期占比 | 0.2 | 仅 DSP 生成参数 |
| `param_9` | 过力矩保护限值 | 未启用 | 需配合 `switch_1` 启用力矩保护 |

`lift_peak_phase` 与 `lift_smooth_time` 是算法开发参数，分别控制摆动区间内的峰值相位与最终髋 / 膝轨迹的平滑时间，不通过面板下发。

> 参数在任务进入后、启动之前生效。行走过程中修改不会影响当前轨迹；下一次起步时按新参数重新生成。接近直腿或触及关节行程限制时，实际抬脚峰值可能低于目标。

## 接口信息

4134 / 4135 的状态与指令接口同被动前向行走，新增目标抬脚高度映射：

| 参数 | 接口映射 |
|---|---|
| 目标抬脚峰值 | `grx.virtual_panel_command_param_3` |
| 启动 / 停止 / 暂停 | `grx.virtual_panel_command_start` / `stop` / `pause` |
| 启用力矩保护 | `grx.virtual_panel_command_switch_1` |
| 参考轨迹、进度与步频 | `rehab.reference_joint_*`、`rehab.motion_ratio`、`rehab.step_frequency` |

## 原理解释

### 算法运行原理

算法先生成普通 DSP 前向步态并计算摆动足端位置，再在摆动区间按目标离地峰值进行逆运动学修正，仅重解摆动侧髋、膝角，最后对轨迹做零相位平滑。补偿在起步前的轨迹生成阶段完成；接近直腿或关节行程边界时，目标抬脚高度可能被运动学可达性限制。4135 仅在此基础上增加速度前馈。

### 康复临床使用建议

- 可在患者已能耐受普通前向行走后，用于需要更多摆动脚间隙的引导训练；不应把高抬腿直接等同于改善独立步行或预防跌倒。
- 从默认或较低目标开始，小幅度增加并逐个评估，避免同时提高抬脚、步长和步速。治疗师应观察实际足部间隙、躯干代偿、骨盆姿态和支撑侧稳定性，而不是只看 `param_3`。
- 目标值不是实际抬脚高度的测量结果。若患者出现疼痛、膝髋活动受限、支撑侧不稳或左右明显不对称，应降低目标或回到普通 DSP 任务，并重新评估适配。
- 4135 的前馈效果依机型协议而异，临床比较不同机型训练结果时不能假设控制作用完全一致。

> 临床建议仅供专业人员参考，不替代医生/治疗师评估、产品说明书及医疗机构安全规范。
