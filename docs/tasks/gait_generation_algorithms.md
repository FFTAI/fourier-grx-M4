# 步态生成算法对比

* TOC
{:toc}

## 任务信息

本页是算法专题，**不对应独立任务值 (TID)**，不能作为运动任务直接下发。页面集中比较 M4L 当前 SDK 中的 VHIP、FHIP、DSP、高抬腿 DSP 与谐波系数五类步态生成方案，并说明它们与助力、负载调参和执行器控制的关系。

适用读者：需要选择运动任务、调整步态参数、开发上位机轨迹预览，或阅读 `fourier-grx` 步态源码的开发与治疗相关人员。

## 模块信息

本页不注册独立模块。各算法通过其对应运动任务或规划器调用，不支持通过模块接口在运行中直接切换生成器。

## 接口信息

生成器的主要输出不是执行器电流，而是以下中间数据：

- 左右髋、膝参考位置与参考速度；
- 质心和足端轨迹（DSP/VHIP/FHIP/高抬腿 DSP）；
- 摆动相、支撑相标志（几何生成器）；
- 单步周期、总帧数、起步/循环/收尾时间边界；
- 由任务层继续上报的 `rehab.reference_joint_position`、`reference_joint_velocity`、`reference_joint_position_max/min` 和 `step_frequency` 等字段。

这些数值描述的是**参考轨迹**。实际关节位置、速度和力矩仍由执行器反馈单独测量，二者不能混用。

## 原理解释

### 算法运行原理

#### 1. 统一控制链路：生成器只负责“参考”，任务模型负责“执行”

五类方案可以归入两条生成路线：

```text
几何生成路线（VHIP / FHIP / DSP）
  参数输入 → 质心与足端轨迹 → 两连杆逆运动学 → URDF 坐标转换
  → 膝限/缩放/平滑 → 位置差分求速度 → 起步、循环、收尾状态机 → PD 控制

高抬腿 DSP
  普通 DSP 全部输出 → 正运动学评估实际足高 → 摆动相二次逆解
  → 零相位平滑 → 速度重算 → 通用执行状态机

谐波系数路线
  预存 Fourier 系数 → 按相位重建关节曲线 → 周期量化与起停拼接
  → 关节限幅 → 通用执行状态机
```

几何生成器都使用二维两连杆逆运动学。若足端相对质心的位移为 `dx,dz`，则：

- `d=sqrt(dx²+dz²)`，并将 `d` 限制在腿可达范围内；
- `q_knee=π−acos((L_thigh²+L_shank²−d²)/(2L_thigh·L_shank))`；
- 髋角由 `atan2(dz,dx)` 与另一组余弦定理共同求得；
- 几何角随后转换为 URDF 的方向、零位和弧度单位，再生成最终参考速度。

生成器之外还有三层执行逻辑，不能与生成算法混为一谈：

1. **播放状态机**：启动前保持实测位置，启动后先进入步态首帧，再执行起步、循环和收尾；停止通常在循环边界处理。
2. **反馈控制**：位置目标经一阶平滑和行程限幅后交给 PD；PD 助力只改变 Kp/Kd，dt 助力只改变轨迹时间推进，负载检测只改变跟踪刚度。
3. **安全与上报**：力矩保护读取实测力矩，参考包络来自生成轨迹，实际跟踪误差来自参考与实测之差。三者描述的对象不同。

#### 2. 五种方案的核心差异

| 方案 | 轨迹的主要来源 | 质心垂直轨迹 | 双支撑处理 | 足高控制方式 | 当前主要用途 |
|---|---|---|---|---|---|
| VHIP | LIPM + 参数化足端 + 在线逆运动学 | 由腿长到支撑点距离的几何关系计算 | 无独立 DSP 段 | 输入 `step_height` 直接生成足端曲线 | 原地踏步、PD/dt 助力前向行走 |
| FHIP | LIPM 水平运动 + 参数化垂直运动 + 在线逆运动学 | 二次抛物线 | 无独立 DSP 段 | 与 VHIP 相同 | 开发者可选的前向/踏步生成器 |
| DSP | SSP 的 LIPM + DSP 的 Hermite 转移 + 在线逆运动学 | SSP 几何高度，DSP 连续 Hermite 有效距离 | 显式分配 `T_dsp` | `step_height` + 平滑摆动脚速度剖面 | 被动前向行走及其膝限版本 |
| 高抬腿 DSP | 普通 DSP 输出后的二次补偿 | 继承 DSP | 继承 DSP | 正运动学评估后按实际离地目标二次逆解 | 需要更大摆动脚间隙的前向行走 |
| 谐波系数 | 预存 Fourier 系数直接重建关节曲线 | 不计算质心 | 已隐含在参考曲线中，不能在线调比例 | 已固化在系数曲线中 | 固定形状、可调节奏的重复步态 |

#### 3. VHIP：虚拟髋关节模型与几何高度约束

VHIP 的水平质心运动采用线性倒立摆近似。若内部步长为 `S_g`、基座高度为 `h`，则：

- `T_step=S_g/v`，`ω=sqrt(g/h)`；
- 支撑点相对坐标中，质心从 `−S_g/2` 向 `+S_g/2` 运动；
- `x(t)=−(S_g/2)·cosh(ωt)+(x_dot0/ω)·sinh(ωt)`；
- 周期边界速度 `x_dot0=(ωS_g/2)·coth(ωT_step/2)`。

它的关键特征是**垂直高度不单独拟合一条自由曲线**，而是根据腿长约束计算：

`z(x)=sqrt((L_thigh+L_shank)²−x²)`

因此质心在步态中点较高、接近换腿边界时较低，垂直形态随水平位置和总腿长自然变化。摆动脚垂直方向采用 `z=h_lift·(1−cos(2πτ))/2`，水平方向默认线性推进，再通过逆运动学得到髋膝角。

原地踏步复用同一生成器，但做了三项改变：

- 质心水平位置与基座高度固定，不形成持续前进位移；
- 摆动脚水平轨迹改为 `x=L_max·sin(πτ)`，步末回到原点；
- 垂直轨迹仍为半余弦，步行周期直接由输入给定，而不是由步长除以步速得到。

**优势**：参数物理意义直观，既能做前向行走又能做原地踏步，便于与 PD/dt 助力组合。

**限制**：没有独立双支撑段；足端和质心模型是简化几何，不表示真实人体质心或患者实际足端已经被测量。

#### 4. FHIP：固定髋模型与抛物线垂直轨迹

FHIP 与 VHIP 使用相同的 LIPM 水平运动、足端半余弦抬升和两连杆逆运动学。两者最容易混淆的地方是：**FHIP 的“固定髋”并不意味着质心高度恒定**。

FHIP 用二次函数显式构造垂直轨迹。令归一化步内相位 `τ=t/T_step`，可将其理解为：

`z(τ)=h_min+4(h_max−h_min)·τ(1−τ)`

端点回到 `h_min`，中点达到 `h_max`。当前实现中的 `h_min` 由总腿长和内部步长近似计算，并附加小幅高度裕量。相比之下：

- VHIP 的 `z(x)` 来自圆几何/腿长约束，垂直形状随水平位移变化；
- FHIP 的 `z(τ)` 是直接给定的抛物线，垂直形状随时间相位变化；
- 两者水平方向都仍是 LIPM，不能把这个差别理解成两种不同的水平动力学模型。

当前公开任务默认没有独立选择 FHIP 的 TID；开发者可在支持的控制模型中使用 `gait_generator_type="fhip"` 选择前向或原地踏步生成器。临床或上位机参数对比时，不应假设它与默认 VHIP 任务的垂直轨迹完全一致。

#### 5. DSP：显式双支撑期与连续重心转移

DSP（Double Support Phase）在 VHIP 类模型基础上，把每一步拆成单支撑期 SSP 和双支撑期 DSP：

- `T_step=S_g/v`；
- `T_dsp=r_dsp·T_step`；
- `T_ssp=T_step−T_dsp`。

**SSP 阶段**：摆动脚完成迈步，质心按 LIPM 从 `−a` 移到 `+a`。足端水平方向采用平滑梯形速度剖面，使离地和落地速度均为零；垂直方向仍为半余弦。

**DSP 阶段**：双脚保持落地位置，质心通过三次 Hermite 样条从 `+a` 继续移动到 `+a+d`。样条端点与相邻 SSP 的位置和速度衔接，避免换腿时质心速度突变。

为了保证前后两步周期衔接，DSP 的质心转移距离 `d` 不是简单等于 `r_dsp·S_g`，而是由闭式关系确定：

- `K=r_com·T_dsp·ω·coth(ωT_ssp/2)`；
- `d=K·S_g/(2+K)`；
- `a=(S_g−d)/2`。

这里 `r_com` 控制 DSP 中段重心转移快慢，当前内部默认 `dsp_com_ratio=0.8`；摆动脚加减速比例 `swing_blend=0.3`。DSP 还会根据腿长几何计算高度，并使有效距离及其斜率在 SSP/DSP 接缝处连续。

**优势**：双支撑占比有明确物理时序含义，换腿过程更平滑，适合需要可调双支撑期的前向步态。

**限制**：`r_dsp` 只改变参考模型中的时间分配，不等于实际人体双支撑比例已被识别，也不自动保证整机平衡。

#### 6. 高抬腿 DSP：从“输入足高”转为“校准后的实际足高”

普通 DSP 的 `step_height` 是逆运动学之前的足端目标。经过髋角缩放和平滑后，最终关节角对应的实际足高会改变。高抬腿 DSP 因此在原 DSP 输出之后增加第二次几何处理：

1. **正运动学评估**：用当前髋膝角计算踝相对髋的位置，并以两脚中较低者作为地面参考，得到原轨迹的实际离地间隙。
2. **构造目标窗**：在摆动区间使用 `w(s)=6x⁵−15x⁴+10x³`，峰值位于 `lift_peak_phase`；目标为 `smooth_max(base_clearance,H_lift·w(s))`，只抬升、不压低原轨迹已经更高的部分。
3. **二次逆运动学**：保持该帧摆动脚水平位置 `x` 不变，仅修改高度 `z`，重新求解摆动侧髋膝角；支撑腿轨迹不变。
4. **约束与平滑**：髋膝角限制在机械行程内，再以当前帧为中心的二项式核进行零相位平滑，最后重新差分速度并计算实际足高诊断值。

需要区分两个高度参数：

- `param_7` / `step_height`：补偿前的 DSP 原始足端抬升高度；
- `param_3` / `H_lift`：经过实际关节轨迹评估后的目标离地峰值，默认 0.10 m，允许 0.05～0.25 m。

接近直腿或关节行程边界时，目标可能不可达，因此 `H_lift` 不是实际足高保证值。TID 4135 仅增加执行阶段速度前馈，不改变上述生成过程。

#### 7. 谐波系数：关节空间曲线拟合与相位回放

谐波方案不再计算质心、足端或逆运动学，而是直接把预存系数转换为关节角度：

`q(φ)=a0+Σ[k=1..K](a_k·cos(2πkφ)+b_k·sin(2πkφ))`

当前 `K=10`，`φ∈[0,1)`。每个关节都有独立系数，左右腿的相位关系已包含在系数中。系数表在生成前已经完成 URDF 符号、零位和弧度转换。

其运行过程为：

1. **选曲线**：4 个髋幅度档 × 4 个伸膝限制档组成 16 组系数；曲线形状在启动前确定。
2. **加时间轴**：步频档给出目标大步时间 `T_stride`，量化为 `N=round(T_stride/Δt)` 帧，实际周期为 `N·Δt`。
3. **按帧求相位**：`φ=(n mod N)/N`，逐帧计算四个关节的位置，再由最终位置差分求速度。
4. **拼接起停**：站立姿态与循环第 0 帧之间使用三次 Hermite 过渡；循环窗包含完整左右周期，保证回跳相位连续。
5. **限幅与执行**：轨迹经髋膝行程限幅后进入通用起步、循环、收尾和 PD 控制流程。

**优势**：步态重复性高，关节包络可直接预览，不需要根据患者腿长在线求解；档位与节奏可以独立选择。

**限制**：步长、步速、腿长、基座高度、抬脚高度和双支撑占比不参与曲线生成；它也不会根据患者实时表现修改 Fourier 系数。

#### 8. 生成器之外的助力、负载与前馈差异

这些功能会改变执行效果，但通常不改变生成器所选的基本方案：

| 功能 | 作用位置 | 对参考轨迹的影响 | 对控制输出的影响 |
|---|---|---|---|
| 被动任务负载检测 | 循环段正机械功率积分 | 不改变几何或谐波曲线 | 前向阈值 30 J、踏步阈值 70 J，超过后 PD 向 hard 爬升 |
| PD 助力 | 启动阶段 Kp/Kd 插值 | 不改变轨迹形状 | `Kp=100+100r`、`Kd=10+10r`，改变误差纠偏强度，关闭自动负载爬升 |
| dt 助力 | 循环段轨迹时钟 | 不改变角度包络，实际周期约为 `T_base/v_play` | `v_play=0.5+0.5r`，PD 固定 medium；自动模式只改变后续播放速度 |
| 膝关节受限 | 生成前的共同参数与生成后的膝角裁剪 | `θ=max(θ_left,θ_right)` 用于双膝，并影响几何基座高度 | 不直接限制实测关节，也不作为独立机械限位 |
| 速度前馈 | 执行阶段 | 不改变基本曲线生成逻辑 | 是否实际下发取决于 FSA v2/v3 协议与机型 |

因此，比较两个任务时不能只看“VHIP 还是 DSP”，还要同时确认 PD 档位、是否开启自动助力、是否启用力矩保护以及机型协议。

### 康复临床使用建议

算法选择应先由工程参数和训练目标共同约束，再由医生/治疗师根据患者活动范围、负重能力、疲劳和疼痛反应确认。可将下表作为选择起点，而不是固定处方：

| 训练或工程需求 | 优先理解的方案 | 选择原因与注意事项 |
|---|---|---|
| 需要明确调整双支撑期 | DSP | 时序含义清晰，但双支撑比例不等于实际平衡保障；仍需外部支撑 |
| 需要原地踏步或 PD/dt 助力 | VHIP | 参数直观且与助力任务对应；PD 调刚度、dt 调节奏，不能混为同一“助力强度” |
| 需要比较不同质心垂直模型 | FHIP 与 VHIP | 适合开发评估，FHIP 不是默认公开任务，启用前需空载验证 |
| 普通 DSP 的实际足部间隙不足 | 高抬腿 DSP | 直接针对最终关节轨迹补偿；从保守目标开始，观察实际间隙和支撑侧稳定性 |
| 需要固定形状、可重复的关节曲线 | 谐波系数 | 便于跨次重复，但不能按患者腿长或实时表现在线个性化 |
| 左右膝伸展限制不同 | 对应膝限任务 + 所选生成器 | 当前取较大受限输入用于双腿，必须确认另一侧也能耐受 |

临床使用中还应统一遵守：

- 先用规划器或空载流程检查参考关节包络，再从保守参数和完整外部保护开始；预览通过不代表患者可以耐受。
- 不要把 `reference_joint_*` 当作患者实际步态，不要把步频、双支撑占比或助力系数直接当作独立步行能力、主动肌力或疗效指标。
- 任何生成器都不识别疼痛、痉挛或跌倒风险。出现异常力矩、疼痛、抵抗、足部触碰、左右不稳定或疲劳时，应停止并重新评估。
- 更换生成方案时，应同时重新核对 PD 档位、力矩保护、速度前馈协议和机型差异，不能只复制上一方案的步态参数。
