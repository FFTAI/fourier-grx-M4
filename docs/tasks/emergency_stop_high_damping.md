# 高阻尼保护（急停响应，M4LT2）

* TOC
{:toc}

## 任务信息

任务值 (TID)： **4600**

适用机型：**M4LT2**

任务描述：

- 当机器人检测到 **硬件急停开关**（ioboard 急停按钮）被触发时，控制程序自动切换到该任务。
- 与直接断电（`TASK_SERVO_OFF`）不同，该任务保持关节上电状态，以 **高阻尼、零弹簧力** 的 PD 模式对旋转关节进行控制：
  - `kp ≈ 0`（实现中取 0.001，固件不允许为 0）：不施加复位弹簧力，关节可被外力被动活动；
  - `kd = 20（默认）`：施加速度阻尼制动力，消耗关节运动能量，防止肢体快速跌落或甩动；
  - 目标位置跟随当前测量位置，每帧实时更新，无回弹效果。
- 该模式可有效降低急停后机器人肢体无控失控的风险，为操作者提供更安全的保护时间窗口。

> ⚠️ **注意**：
>
> 此任务由控制程序在 `flag_emergent_stop` 被置位时**自动触发**，不建议通过手柄或 User 接口手动切换到该任务。
> 急停解除后，机器人将继续保持高阻尼状态，需手动切换其他任务（如 `TASK_STAND_CONTROL`）才能恢复正常运动控制。

任务参数：

该任务无可配置参数。PD 参数 `kd` 值需由硬件工程师在 `fi_algorithm_m4l_rotary_joint_high_damping.py` 中根据实际关节惯量调参。

## 触发条件

该任务由以下三种条件之一触发：

| 触发源 | 触发条件 | 说明 |
|--------|---------|------|
| ioboard 急停开关 | `ioboard.emergency_state == True`（置位 `flag_emergent_stop`） | 用户按下机器人背包上的硬件急停按钮 |
| 全执行器通信超时 | 所有执行器连续超时 ≥ 1.0 s（拍数按控制周期折算；置位 `flag_emergent_stop`） | 通信异常导致的保护性触发 |
| 上位机心跳超时 | `flag_host_heartbeat_timeout` 置位 | 上位机与机器人通信中断时的保护性触发 |

## 模块信息

该任务暂无独立模块指令，不支持通过模块接口进行分关节控制。

## 接口信息

状态接口：

| 接口参数     | 接口映射关系                              | 说明                          |
|------------|----------------------------------------|-------------------------------|
| 急停标志     | `robot.flag_robot_emergent_stop`       | 高阻尼任务运行期间始终为 SET    |

指令接口：

该任务无需额外指令参数，由控制程序自动触发；已在 M4LT2 的任务表中注册，但不建议由上位机直接下发 TID=4600 启动。

## 与执行器失能的区别

| 特性         | 高阻尼保护（4600）              | 执行器失能（36）               |
|------------|-------------------------------|-----------------------------|
| 触发方式     | 硬件急停开关自动触发（M4LT2）    | 手柄 logo 键 / User 接口手动触发 |
| 关节上电状态 | 保持上电，输出阻尼力矩            | 断电，无力矩输出                |
| 安全特性     | 软制动，肢体不会瞬间跌落          | 机器人立即瘫软                  |
| 恢复方式     | 手动切换其他任务                 | 需重新上电并切换任务             |

## 原理解释

### 算法运行原理

高阻尼保护的核心是把普通 PD 控制器改造成**以当前位置为中心的速度耗散器**：

1. **保护触发**：硬件急停、全执行器通信超时或上位机心跳超时置位保护标志，任务管理器自动切换到 TID 4600，无需等待当前步态到达循环边界。
2. **每帧跟随实测位置**：令 `q_ref[k]=q_meas[k]`，并将位置增益设为 `Kp=0.001`（协议不允许直接取零）、速度增益设为 `Kd=20`。位置和速度误差形成的力矩可近似写为 `τ=Kp(q_ref−q_meas)+Kd(ω_ref−ω_meas)`。
3. **形成阻尼力矩**：由于位置参考与实测位置相同，位置项近似为零；速度参考被清零后，主要输出为 `τ≈−20·ω_meas`，方向始终与当前运动相反。其瞬时机械功率 `P=τ·ω≈−20·ω²≤0`，因此主要耗散关节动能，而不是向固定姿态注入复位力。
4. **清除继承输出**：任务在 component 与 standalone 路径都将速度和力矩前馈目标清零，避免上一任务残留的前馈叠加到阻尼力矩上。静止时阻尼力矩也接近零，所以关节不会主动回到原站姿。
5. **解除后保持**：急停信号消失不会自动退出该模式，仍由后续任务显式接管。高阻尼能减小快速甩动，但没有足够的位置项支撑持续静载，也不具备患者防跌倒或姿态识别功能。

### 康复临床使用建议

- 把高阻尼理解为争取处置时间的软制动，而不是安全站立或继续训练模式。触发后操作人员仍需立即承托患者与设备，检查疼痛、皮肤、关节位置及可能的机械伤害。
- 急停解除不会自动恢复训练。应先查明触发原因、确认通信和硬件状态，再按机构流程选择失能、转移患者或重新进入准备任务；不要在患者仍穿戴且原因不明时直接恢复步态。
- 不建议把 TID 4600 当作常规暂停或主动放松训练功能。阻尼大小与速度和机型相关，患者仍可能缓慢下落或移动，外部防跌倒保护必须保持。
- 若同一训练反复触发急停或心跳超时，应停止临床使用并排查配置、网络和设备问题。

> 临床建议仅供专业人员参考，不替代医生/治疗师评估、产品说明书及医疗机构安全规范。

## 更新日志

- `fourier-grx` v4.4.3 版本新增该功能（仅 M4LT2）。
- `fourier-grx` v4.4.43 版本起，上位机心跳超时也会切换到本任务（此前仅硬件急停与全执行器超时触发）。
- `fourier-grx` v4.4.71 版本：本任务的日志改为**区分触发成因**——原先无论何因都打印 "Emergency stop detected"，现在按 `flag_emergent_stop` 与 `flag_host_heartbeat_timeout` 分别报告（同时成立时以 " and " 连接，均不成立时报告为手动进入）。因 `flag_emergent_stop` 由 ioboard 急停按钮与全执行器通信超时共用，故再借 `flag_all_actuator_timeout` 区分：成立时报 "Emergency stop or all-actuator communication timeout"，否则报 "Emergency stop (ioboard button)"。同版修正本页「连续超时 ≥ 50 个控制周期」的陈旧表述（实为 1.0 s，拍数按控制周期折算，T2 200 Hz 下为 200 拍）。
- `fourier-grx` v4.4.73 版本：高阻尼任务在 component 与 standalone 两条控制路径下都会将速度 / 力矩目标清零，避免任务切换后继承上一任务的前馈指令。
