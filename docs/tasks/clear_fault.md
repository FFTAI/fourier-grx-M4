# 清除错误

* TOC
{:toc}

## 任务信息

任务值 (TID)： **34**

任务描述：

- 清除执行器的错误状态，如果对应错误码可以通过重启来清除，则机器人可以继续工作；如果对应错误码无法通过重启来清除，则需要排查硬件故障修复。

任务参数：

该任务无可配置参数。

## 模块信息

该任务暂无独立模块指令，不支持通过模块接口进行分关节控制。

## 接口信息

状态接口：

| 接口参数   | 接口映射关系                  | 说明                                            |
|--------|-------------------------|-----------------------------------------------|
| 任务启动标志 | `task.flag_task_start`  | 清除过程中为 SET                                    |
| 任务结束标志 | `task.flag_task_finish` | 清除操作完成后置为 SET（可通过 `grx.robot_error_codes` 确认结果） |

指令接口：

该任务无需额外指令参数，发送 TID=34 即可触发。清除后请检查 `grx.robot_error_codes` 是否为空列表以确认错误已消除，如错误码仍存在则需排查硬件故障。

## 原理解释

### 算法运行原理

本任务是故障锁存位的复位流程，而不是故障诊断算法：

1. 进入任务后向全部执行器发送 `CLEAR_FAULT`，请求清除允许复位的错误状态，并清空运动目标。
2. 随后写入零力矩并恢复 `NONE`，防止清错过程与上一任务的力矩输出叠加，最后切回 `TASK_IDLE`。
3. 上层通过 `grx.robot_error_codes` 读取执行器实际上报的错误码，判断锁存位是否确实清除。任务结束本身并不等于所有故障均已消失。

过流、过温、编码器异常、通信中断和机械卡阻都有各自的物理原因；本任务既不确定原因，也不会修复它们。不可复位的错误会继续保留，因此清错后的错误码复查是控制链路的一部分。

### 康复临床使用建议

- 清错前先停止训练并保护患者，记录错误码及发生时的任务、姿态和异常表现；只有明确原因且确认可安全恢复后，才可按流程清错。
- 清错成功不代表患者可立即继续原强度训练。应重新检查绑带、关节活动空间、零点和设备状态，并从低风险准备动作开始。
- 错误反复出现、原因不明或伴随疼痛/机械异常时，应终止本次使用并转工程检修，不要连续清错强行运行。

> 临床建议仅供专业人员参考，不替代医生/治疗师评估、产品说明书及医疗机构安全规范。
